The two C enumerators use different search traversals and maximality computations. They share the mathematical problem, target indices and sharding convention, but not enumeration code. The brute force program shares no producer code or data except the mathematical definition. The archive audit reads data generated by both programs and is not a new enumeration.

```sh
cc -O3 -std=c11 programs/line_rows.c -o /tmp/c3_rows
cc -O3 -std=c11 verification/determinant_check.c -o /tmp/c3_det
python3 verification/bruteforce.py

```

The first three checks were run as shown; the n=8 run used the equivalent inline Python now in `verification/check_n8.py`. Full output is in `verification/logs/`. The n=1..7 replays match every stored cell, and the brute-force checks match n=1..4. The archive audit verifies all 512 shard receipts and compares each aggregate n=10 cell to the table. The n=9 stored reference profiles were also compared with the table; see `verification/logs/n9-reference.txt`.
